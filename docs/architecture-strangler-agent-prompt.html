# Task: Remediate CoreVideo Pro architecture hotspots (maintainability + reliability)

You are working in the **CoreVideo Pro** repo (`iamfatness/CoreVideoPro`).

## Product constraints (do not violate)

Read and obey before writing code:

- `docs/FOCUS_PLAN.md` — authoritative cut line for the next 90 days (golden path + ISO V+A, NDI, SRT, browser BR-1; HOLD ML face framing; OUT DeckLink/AJA/ASIO/macOS/etc.)
- `CLAUDE.md` — build/run, CoreMessagingXP crash class, lock order, Zoom teardown rules
- `README.md` — as-built multi-process architecture
- `docs/alpha-plan.md` / `docs/beta-plan.md` — verification context only; **FOCUS_PLAN wins on cut line**

### Non-goals (hard stop)

- Do **NOT** add product features (no ISO implementation, NDI polish, new sources, VST-r2, UI redesigns) unless a *tiny* seam is required to extract a module.
- Do **NOT** rewrite the media pipeline, switch UI frameworks, merge processes, or introduce a new IPC style.
- Do **NOT** “clean up” Pro tools (VST / routing / DSK / Companion) for aesthetics.
- Do **NOT** drive-by reformat unrelated files or expand protocol surface without parity updates in all three mirrors.

### Goal

Make the codebase **safely changeable** for the focus spine:

`Join → Magic Scene → Take → Record / Stream / Vcam` (+ later ISO / NDI / SRT / browser)

by decomposing god objects and clarifying boundaries with a **strangler pattern** — not a big-bang rewrite.

**User-facing improvement to optimize for:** fewer mid-show regressions, safer spine merges, clearer Show vs Pro ownership — not new buttons.

## Architecture issues (priority order)

### P0 — `StudioViewModel` god object (do this first)

**File:** `native-shell/CoreVideoPro.WinUI/ViewModels/StudioViewModel.cs` (~12k+ lines)

**Problem:** One type owns inputs, scenes, Magic Scene / Set & Forget, transport (record/stream/take), audio, graphics, Zoom shell state, surface/multiview binding, automation. Highest regression and agent-collision risk in the repo.

**Required outcome:**

1. Inventory responsibilities (regions, method groups, dependencies). Put the inventory in the PR description.
2. Extract **vertical slices** into focused types (services / child view-models / coordinators). Preferred slices (order by golden-path value):
   - `MagicScene*` / `SetAndForget*` / production mode
   - `Transport*` (record / stream / take / preview arming)
   - `ShowInput*` / roster assignment / auto-assign
   - `Graphics*` (lower-thirds / captions / overlays coordination)
   - Surface / multiview binding coordination (only if still tangled with production state)
   - Leave deep Pro audio/routing where it already lives if partially split; do not re-home the entire console in one PR
3. `StudioViewModel` becomes a **composition root + bindings façade** (shrink substantially). Partials are OK only as a short intermediate — prefer real types over permanent partial sprawl.
4. **Behavior parity** on the golden path unless you fix a clear bug found during extraction (call it out explicitly).
5. Preserve WinUI rules from `CLAUDE.md`:
   - CoreMessagingXP `0xc000027b` — never rebuild bound collections at frame rate; keep throttle/diff-in-place patterns
   - UI-thread marshaling for control/surface updates
   - Do **not** reintroduce per-tile swap chains; keep core-composited multiview model

**Acceptance (P0):**

- [ ] WinUI / MediaCore / Control tests still pass for touched areas
- [ ] Characterization tests added *before* moves when logic was untested
- [ ] Extracted types own Magic Scene + transport at minimum (inputs if time)
- [ ] Document before/after LOC or method-count for `StudioViewModel`
- [ ] No new public media protocol unless unavoidable

## Method (mandatory)

1. **Explore first** — inventory god-file regions, dependency graph, existing tests, any partial extractions already started.
2. **Plan in the PR body** — slices, order, risk, test commands.
3. **Strangler, incremental PRs preferred:**

   | PR | Scope |
   |----|--------|
   | **PR1** | Inventory + extract Magic Scene / production mode + Transport façade + tests |
   | **PR2** | Show inputs / roster assignment |
   | **PR3** | Graphics coordination (if still bloated) |
   | **PR4+** | C++ MediaCore / compositor / JsonRpcServer splits |

   If forced into one PR: separate commits per slice. Prefer shipping **PR1 alone** if context is limited.

4. **Characterization tests before moves** — lock current behavior, move, keep green.
5. Match existing patterns: naming, nullability, construction/DI already used in `native-shell`.
6. Update `CLAUDE.md` only if operational rules or entrypoints change.

## Hard technical constraints

- Three processes: WinUI shell, `corevideo-native`, Zoom engine subprocess.
- IPC: JSON-line commands/snapshots; program/preview via keyed-mutex DXGI shared textures; Zoom I420 shared memory.
- Audio/output stays off the render lock (Phase 2 ~50 Hz worker).
- Secrets remain DPAPI; support-bundle redaction tests stay green.
- I420 vs BGRA: Zoom frames use `hasI420()` paths — do not break blank-tile regressions.
