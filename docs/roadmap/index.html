The ritual. How we run each week

Demos are the heartbeat. Each sprint targets one capability that we can show working in the real native app — not a slide, not a passing test.

🎯 One demoable goal

Each sprint commits to a single capability with a written demo script and exit criteria, agreed Monday.

📺 Friday demo

15-minute live run-through against a real (or realistic) scenario. If it can't be demoed live, it isn't done.

✅ Definition of done

Works in the packaged/dev native app, reviewed, merged. Tests are necessary but not sufficient.

🔁 Adjust & commit

Re-scope from what we learned, then lock the next sprint's single goal.

The road ahead. One demo per week

Each card is a sprint: its single goal, the demo we'll show on Friday, what "done" means, who drives it, and the main risk.

Sprint 1 · NEXT

First Live Demo — Join & See Feeds

week 1
Demo: join a real Zoom meeting and watch live individual participant tiles appear, with the roster and the active speaker highlighted — in CoreVideo Pro, not OBS.

Goals

  • Build the vendored capture engine on the dev machine against the Zoom SDK
  • Wire I420 → RGBA thumbnail → IPC push → <canvas> tiles
  • Real join via ZoomMediaSpineSessionController; map roster + active speaker

Exit criteria

  • Live video for ≥3 participants, <1s to first frame
  • Roster + active-speaker correct against the real call
  • Runs in the dev native app end-to-end
Codex B + dev-machineRisk: SDK raw-data privilege; first dev build
Sprint 2

Switch the Show

week 2
Demo: build a 2–3 person show live and cut between layouts — grid, speaker focus, PIP — with lower-thirds from real Zoom names.

Goals

  • Real feeds drive scenes/layouts; preview → Take
  • Magic Scene on live participants
  • Auto lower-thirds from real display names/roles

Exit criteria

  • Operator cuts cleanly between ≥3 layouts live
  • Magic Scene produces a sensible show from the call
Agent ARisk: layout perf with live frames
Sprint 3

Output It

week 3
Demo: record a real 1080p MP4 of the show and/or go live to an RTMP destination.

Goals

  • GPU compositor renders the program (D3D11 adapter)
  • Record to MP4 via the hardware encoder adapter
  • RTMP push via the output-sender adapter

Exit criteria

  • Stable 1080p MP4 plays back clean
  • Live RTMP stream visible on a platform
Codex B + dev-machineRisk: encoder/compositor on real GPU
Sprint 4

Make It Sound Right

week 4
Demo: a full webinar segment with balanced per-participant audio and real-time captions on the program.

Goals

  • Engine audio path → program mix
  • Per-source leveling + noise suppression
  • Real-time captions wired to a transcription source

Exit criteria

  • Audio balanced without manual riding
  • Captions track the program with usable latency
Codex B + Agent ARisk: caption latency/cost
Sprint 5

Run It Hands-Off

week 5
Demo: an auto-produced show — screen share + Set & Forget directing the cuts, brand kit applied — with minimal operator input.

Goals

  • Set & Forget auto-director on live signal
  • Screen-share layout switching
  • Brand kit (logo/color/font) applied automatically

Exit criteria

  • A webinar runs itself for a sustained segment
  • Manual override always wins, one-click back to auto
Agent ARisk: director jitter/holds

Open decisions & risks. Resolve early

  • Converge the two Zoom capture paths. The vendored proven plugin engine vs. Codex's from-scratch ZoomMeetingSdkAdapter. Pick one before Sprint 1 wiring so effort converges — recommendation: ship Demo 1 on the vendored engine.
  • Zoom raw-data privilege. Clean per-participant video needs the Meeting SDK raw-data entitlement on the app — confirm it's enabled before Sprint 1.
  • Dev machine for native builds. The Zoom SDK / GPU / encoder code can't be built or validated in the CI container — it needs a real Mac/Windows box (Codex building locally).
  • CI test flakiness. The full UI test suite hits timeouts in the slow sandbox; CI gates on CodeQL today. Stabilize/segment vitest before relying on it as a gate.
