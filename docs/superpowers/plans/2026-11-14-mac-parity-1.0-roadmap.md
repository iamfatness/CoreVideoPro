## 2. What the audits changed about how to think of this

1. **Three platform pieces gate most of the Swift work.** The shell gap is real,
   but the long poles are underneath it:
   - **Metal graphics backend.** `MediaCore.cpp:1256` refuses every
     `graphics-*` command unless `ICompositor::supportsGraphicsInstances()`;
     only D3D11 returns true (`D3D11CompositorAdapter.cpp:268`). The template
     rasterizer `src/compositor/CompositorOverlayRaster.cpp` (739 lines) is
     D2D/DWrite and compiled only under `COREVIDEO_WITH_D3D11`. Graphics logic
     (instances, templates, crawls, motion) is shared and tested on Mac CI —
     only the pixels are missing. Gates: Graphics Operate, Designer, crawls,
     datasets, feeds, Shot Layouts, social cards.
   - **A control surface.** `mac-shell` has no HTTP/WS/OSC listener at all.
     Gates: Companion/Stream Deck Take (named in the 1.0 manual-control
     decision, `docs/reference/first-release-scene-control.md`), Volt rundown
     (#1201), and every `/snapshot`-driven QA script.
   - **Comms in the Mac Zoom engine.** Pro ported ZComms from its commit
     `168a572`, which already contains a Mac adapter
     (`talkback_sdk_mac.{h,mm}`); only the Windows one was copied
     (`PORTED.md:12`). Integration, not SDK research.
2. **"Touched `native/`" no longer implies "reaches Mac".** Several fixes in
   this window landed only in Windows-only `native/` modules (MF encoder, D3D11,
   WASAPI, WinUI capture, `main.cpp` engine). The Mac twins
   (`AVFoundationEncoderAdapter.mm`, `MetalCompositorAdapter.mm`,
   `main-macos.mm`) must be checked per fix. `docs/mac-parity-plan.md` §5's
   assumption holds only for platform-neutral core code.
3. **Scope that drops out:**
   - Auto director / Set & Forget / Magic Scene — **retired for 1.0** (owner
     decision 2026-11-09). `AppModel.sceneAutomationAvailable == false`.
   - OHG — deliberate non-port (owner ruling 2026-09-20).
   - EngineHost (#960/#961) — Windows-only, off by default in 1.0.
   - NDI graphics key — the NDI output path is Windows-only.
4. **Audit correction.** The graphics audit's row 4a ("manual Hide vs Auto is a
   live Mac bug") is **moot**: `autoDirectEnabled` can only be set as
   `enabled && Self.sceneAutomationAvailable` (`AppModel.swift:1879`), which is
   false, so `evaluateAutomationLowerThird` always retires. Re-check it only if
   Auto returns. Every other headline finding below was spot-checked against
   the code before inclusion.

### M2 — Control surface on Mac

The Windows registry (`CoreVideoPro.Control`, plain `net9.0`) is a hardcoded
action list with a compile-time dispatch switch into the WinUI view model, so
it cannot be reused as-is. **Recommended:** a Swift-native server
(Network.framework) that implements the *same* action manifest and wire
contract — HTTP :8011 / WS / OSC `/cvp/...` — and is held to it by running the
existing contract fixtures against both hosts. Start with the subset 1.0 names
(scene select, Take, FTB, record/stream) and Companion's module
(`companion-module-corevideopro`), then grow to full coverage.

   (no longer gated on a decision).
3. **Release: signed + notarized.** The owner's Apple Developer account is
   live on this Mac: identity `Developer ID Application: John Wallace
   (42394L3353)`, and the notarytool keychain profile is named
   **`CoreVideo Plugin`** (proven end to end for the OBS plugin
   2026-09-05: hardened runtime, `find -depth` nested signing,

   - **M0.11 (new, S):** sign local dev bundles with the Developer ID so

     plugin's recipe into `scripts/make-macos-shell-bundle.sh`.
   - **M9.2 (virtual camera) is UNBLOCKED.** A CoreMediaIO Camera Extension
     needs a provisioning profile carrying the System Extension capability
     from the developer portal — an owner portal step to schedule at the
     start of M9.2, not a blocker.
4. **Live tests: all available** when their milestones arrive — co-host
   Zoom meeting (M7.3), Twitch channel (M6.3), YouTube live stream (M6.2),
   Companion / Stream Deck (M2.2).

## 6. Rules carried into every milestone plan

- **Backlog first** (CLAUDE.md: `docs/BACKLOG.md` is the single ranked list).
  Each M0 defect is a new defect: file it as a GitHub issue labelled
  `backlog` with a row in its tier before work starts, and let the owner
  re-rank. M1–M9 enter the backlog as one tracking issue per milestone.
- **North star holds on Mac.** M3's Core Text raster runs on the async
  preparation path exactly like D2D on Windows — never on the render tick —
  and M3.3 includes a `mac-show-drill.py --load 8` run with a graphics cue
  showing no delivery regression (per-frame delivery, not mean fps).

- Write each milestone's implementation plan to
  `docs/superpowers/plan-authoring-rules.md`: interfaces + behaviour + complete
  tests, no implementation bodies, a "Mutations to run" block per task.
- For every Windows behaviour ruling ported, quote it in the task and point at
  the Windows test that proves it; the Swift test must fail on the old Mac
  behaviour first.
- Every fix that touches a Windows-only `native/` module gets a named Mac-twin
  check (§2.2).
- Pixel claims are verified with pixels: Metal readback tests or the
  `COREVIDEO_SHELL_SNAPSHOT` harness, never by reading code.
