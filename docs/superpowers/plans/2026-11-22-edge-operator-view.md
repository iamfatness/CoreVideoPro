# Implement Edge feed visibility in Pro Sources

Tracking: [#1227](https://github.com/iamfatness/CoreVideoPro/issues/1227). Contract: [Edge feeds in Pro Sources](../specs/2026-11-22-edge-operator-view-design.md). Work order lives in [BACKLOG.md](../../BACKLOG.md).

## Pro receive path and the first operator-visible slice

- **Extend the current receiver.** Add a focused native parser and observation reducer beside `native/src/modules/NdiReceiveCaptureAdapter.cpp`. Match the discovery convention on the source name while retaining the exact name for hashing. Attach the optional Edge observation to the current receive channel. Parse only bounded metadata associated with accepted video while the SDK frame is valid. Test expiry and receiver lifetime with an injected monotonic time input. Continue to use the existing receive path for video and PCM.
- **Carry the observation to Sources.** Extend `CaptureDeviceInfo` in `native/src/modules/Interfaces.h`, its publication in `native/src/core/CoreStateCapture.cpp`, and the typed capture observation in `contracts/observation.schema.json`, `CoreProtocolModels.cs` and `CoreProtocolParser.cs`. Check the model propagation into `ProductionModels.cs` and the Show Inputs projection. Use a focused Sources presentation model and view component alongside `SourcesPage`. Group by observed host/name where available, render slots in numeric order, and retain the picker and assignment paths. Add a compact row detail for the guest, separate sender and receiver counters, and video state. Keep stale guest labels out of current status. Landing the parser and its Sources consumer together gives the first Windows operator slice using existing Edge builds and their legacy guest metadata.
- **Legacy fixture and negative controls.** Advertise two Edge nodes with the same node display name and distinct SDK host labels, slots 1 and 8 on the first, and slot 1 on the second. Include a regular NDI sender, an NDI sender with a similar but invalid slot suffix, and an SRT source with an existing assignment. For one attached Edge source, send independently named guests Avery then Morgan at 1280×720. Assert the originally assigned device ID and scene route are unchanged, the label becomes Morgan, and unrelated rows retain their bindings. Change the grouping key to ignore the host, and change the route key to include guest text, separately. The corresponding grouping and binding assertions must fail. Cover the unwrapped name form as well.
- **Receive loss and restart controls.** Supply moving video and isolated audio first. Then advance the manual clock past the receiver's 1,500 ms window without video while permitting audio, and verify Video stalled with the source still assigned. Expire metadata at more than five seconds while continuing video without metadata and verify Receiving video with no current label. Restart the receiver and wait for valid video plus a new sample before showing the new guest. Mutating the stale-state or metadata-clear branch must fail the appropriate assertions. Include an unsupported version, duplicate attribute, invalid UTF-8, oversized packet and malformed number; these inputs must leave valid A/V working. Exercise the actual Sources snapshot consumer so a producer-only field that never reaches the page fails the test.

## Edge sender evidence

- Update Edge's `native/src/edge/FeedSender.cpp` and `docs/PROTOCOL.md` to emit the optional versioned skip sample on the existing NDI frame metadata. Keep the advertised names, `guest` and legacy `zoom_id` fields so older builds stay compatible. Sample the current worker's existing ring-skip count, preserving the baseline and reset semantics; keep SRT and recording paths separate.
- Exercise the production sender with an NDI probe fixture. Advance a synthetic video ring from sequence 2 to 18 so seven frames are superseded. Independently induce two receiver frame rejections in a controlled adapter fixture and assert the Pro projection retains seven Edge skips and two Pro drops as distinct fields. Verify a replacement worker can report zero after the earlier value of seven. Removing sender publication, replacing the Pro drop count with the sender value, or holding the old count after restart must each turn the corresponding evidence red. A legacy sender with an identical video stream must still show its guest while Edge skips remain absent.
- Keep fixture/protocol cases for both repos with the consumer slice. Run the relevant Pro native NDI tests, capture observation/parser and Sources tests, then the documented Windows `npm run test:gate`. Run Edge's native tests and its NDI fake-engine validator using the NDI runtime. In installed or lab qualification, a missing NDI runtime is missing evidence and must be reported explicitly.

## Mac Edge to Windows Pro qualification

1. Build an Apple Silicon Edge candidate from current Edge `main` with the relevant changes from `mac-app` and `mac-native`. Bring the Avalonia app, POSIX node, Zoom engine bundle and platform recorder together. Verify the installed app opens, OAuth returns to it, Keychain works, the Zoom helper launches, the actual NDI runtime loads, and raw media can be granted in a live Zoom meeting. Run native and .NET suites and record the result of each fake-engine CI variant, including the known separate SRT gate. The [native branch CI run](https://github.com/iamfatness/CoreVideoEdge/actions/runs/42733138298) proved compile and engine bundling and exposed the SRT receiver failure.
2. On physical Apple Silicon hardware, run the packaged Edge candidate against packaged Windows Pro on a wired LAN with the NDI runtime on both systems. Route four live Zoom guests to Edge slots 1–4 and the matching Pro Show Inputs. Use identifiable pictures and isolated audio. Include one guest who never speaks and another who provides repeated timed picture/audio cues. Start four 1080p30-target ISOs and receive four NDI feeds for at least 60 minutes. Log actual incoming resolution and measured cadence separately from targets and ISO dimensions. Decode each ISO and representative Pro captures, show all four inputs can reach Preview and Program as assigned, and compare per-source A/V offset and drift at the start and end against the Windows baseline. A sampled run without decodable audio/video evidence or a matching baseline leaves the relevant measurement unqualified.
3. In the same Zoom session after the steady-state measurement, reassign a guest, restart an NDI sender, and move a routed guest through a breakout and back. Confirm the intended rows change, stale values clear, and restored A/V reaches the same existing Pro inputs. Record each interruption duration, recovery and any manual intervention. Record the least reliable case and include Edge skips, Pro drops, ISO writer losses and held/repeated frames as separate evidence. For the uninterrupted run, require playable, finalized ISOs for all four slots, full audio-track duration for the silent guest, no ISO writer losses, no unexplained capture discontinuity and no unexplained A/V drift versus the baseline. Keep artifacts tied to the exact Edge and Pro commits and installed builds.
4. Once the four-source result is recorded, repeat at eight sources to establish the capacity of the chosen Mac. Treat a signed and notarized public Edge package, Mac talkback and Mac SRT as separate release decisions. The engineering proof for this issue uses the NDI path and an authorized internal Edge build.
