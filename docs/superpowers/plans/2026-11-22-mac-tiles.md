# macOS parity Phase 3: CoreVideo Tiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Mac operator can create, cue, edit and Take a CoreVideo Tiles auto-reflow wall that matches Windows 1.0 in wire, subscriptions, identity, inspector layout and pixels, proven on Metal and in a live meeting.

**Architecture:** The shared C++ core already parses, admits, lays out, animates and keeps continuity for a `tiles` node (spec §3.1-3.2, §4.1). Metal already has the decoration shaders, but nothing proves their pixels. This plan proves and fixes Metal pixels (N1). It then ports the Windows shell policy to Swift as pure types, tested against fixtures that the Windows C# code produced or confirmed (S1-S3). The SwiftUI inspector copies the Windows Scene Builder's centre and inspector columns, with tabbed and individually scrolling inspector pages (S4-S5). A1 runs a quiet-machine drill and the owner's live check.

**Tech Stack:** Swift 5 / SwiftUI (mac-shell, in-binary `COREVIDEO_SHELL_TESTS` harness), C++17 + Metal (native, gtest), Objective-C++ (Zoom engine), C# xUnit (Windows oracle tests), Python (`scripts/mac-show-drill.py`), Node (`scripts/validate-tiles.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-15-mac-tiles-design.md` (read §3 and §5 first). The master plan rows are in `docs/superpowers/plans/2026-11-15-mac-parity-master-plan.md` (Phase 3, CoreVideo Tiles). Phase 4 rows N2, C1 and S6 are **out of scope** here.

## Review Focus

These are inputs and failure modes that the spec implies but that no slice is organised around. Each line names the task that owns its pinning test.

1. **A prefs file whose `tiles` object is partial or newer.** Older builds omit keys and later builds add some. Swift's synthesized `Decodable` treats a missing non-optional key as fatal, and one failed scene decode drops the **whole** prefs file. Expected: defaults fill in and nothing else is lost. Owner: Task 6 (`testAPartialOrNewerTilesObjectDecodesWithDefaultsAndKeepsEveryOtherPref`).
2. **An inspector slider dragged for 40 ticks.** Windows hit a stack overflow from a two-way binding echo (`StudioViewModel.cs` comment above `_galleryEditGuard`) and a selection freeze (`docs/archive/qa/tiles-incident-2026-09-07.md`). Expected: one scene sync per debounce, no re-entrant write, no loop. Owner: Task 16 (`testAFortyTickSliderDragSendsOneSceneSyncWithTheLastValue`).
3. **A Take while the Members selection is empty or just cleared.** This crashed Windows (`docs/archive/qa/take-empty-tiles-selection-2026-09-07.md`). Expected: no crash, the editor shows defaults, saved overrides are untouched. Owner: Task 19 (`testATakeWithAnEmptyMemberSelectionLoadsDefaultsAndKeepsOverrides`).
4. **A core respawn with the wall on Program in a meeting.** Expected: the new generation gets the `tiles` node on both buses and a spine push. An unknown-meeting tick never wipes the sticky-audio latch. Owner: Task 11 (`testACoreRespawnResendsBothWallsAndTheSpineAndKeepsTheLatch`).
5. **A guest who leaves and rejoins under a new session id while saved in a manual slot or on never-show, plus a second guest with the same display name.** Expected: the slot follows the person (persistent id, else a unique name), and a duplicate name seats nobody. Owner: Task 13 (`testARejoinedGuestKeepsTheirSlotAndADuplicateNameSeatsNobody`).
