# Graphics Phase 3 Slice 6 — moderated social feeds

Tracks [#1113](https://github.com/iamfatness/CoreVideoPro/issues/1113) and carries forward the moderation requirements from [Slice 5](2026-11-04-graphics-phase3-slice5-push-feeds.md). Start with YouTube live chat. X, Twitch and LinkedIn remain separate adapters and must pass the same acceptance cases plus their provider checks.

## Operator workflow

In Graphics, open **Social review**, enter the video ID for one public YouTube livestream and supply a locally protected YouTube Data API key. Connect explicitly. Show the selected video, connection status and a private list of text messages with author, message, time and decision. Show YouTube as the source in review and on the graphic. Disconnect, replace the stream, or clear local data from the same panel.

Select one item, read the complete text that will be rendered, then choose **Approve** or **Reject**. Show is a separate action on the selected approved item. Approval alone sends no native command and leaves Program unchanged. Keep the exact approved text, author and attribution together through Show. Use a dedicated, bounded native graphic for a single item. No custom text override, names-list conversion, data-table export, automation, live follow or bulk approval. Hide is available even if the connection has dropped. Show the item as on air only when confirmed by the native snapshot. The native card ends after 15 seconds even if the console detaches.

## Eligibility and ownership

- The console owns one connected show and source generation. Identity is generation plus provider message ID. Every change to the normalized visible fields creates a new monotonically increasing revision for that ID. Approval and rejection require the exact revision displayed in review. An unchanged replay leaves the existing decision intact.
- A changed payload returns to review. Deletion, retraction, tombstone or local withdrawal invalidates every version of the item. Retain bounded tombstones through reconnect within the same generation. On loss of ordering, overflow of the tombstone budget or uncertain continuity, clear eligibility and require a fresh generation. Never evict a tombstone and continue accepting replays in that generation.
- Disconnect, revoked or invalid authorization, source replacement, or show change clears approvals and makes old callbacks inert. Provider content, decisions and cursors live only in the active console session. No chat payload, author, API key or cursor goes into show files, telemetry, crash annotations or logs. Clear local data cancels the source, erases local content and deletes the protected key.
- Process provider invalidation and final Show submission on the same serialized owner. Check once before native preparation and again after the prepare wait, immediately before submission. If an invalidation wins before submission, retire private work. If Show was already submitted, invalidate and hide the native instance promptly on edit, removal or disconnect. Use native revision and epoch checks and do not show a newer revision using an older approval.
- The social Show path uses a private native cue with ride-Take disabled. Keep that cue and instance out of the playlist, Shot Layouts and generic control action target resolution. Ordinary Take, Show-from-cue, hotkeys and the control API cannot use a social item. Only the dedicated operator Show action can consume the approval. Validate those negative paths in the running shell as well as the service.
- Bound the UTF-8 message to 192 bytes and the author to 80 bytes for the first on-air card. Preserve the text as plain text and apply the same normalization before review and render. Reject oversize or undisplayable items rather than silently changing the approved content. Bound the queue and item lifetime, expire approvals with the item, and clear the native graphic when its shown item expires.

## YouTube transport and access

For the public-stream beta, use an operator-provided, API-restricted key. Send it only to Google over TLS in an API-key header, keep it out of the URI, reject redirects, and do not use the Zoom broker. Resolve the supplied video ID using `videos.list` and its active chat ID. Use `liveChatMessages.list` with a bounded response and an in-memory continuation token. The published streaming schema omits explicit deletion and retraction events. The paged API schema carries both, so it is the first adapter transport. Honor the provider interval with a local 15-second minimum. Stop on an ended chat or authorization failure. Use bounded backoff for transient transport or quota failures. Reconnect never restores a decision invalidated by a disconnect. Do not add OAuth for private or members-only chats in this slice. [Paged chat](https://developers.google.com/youtube/data/live/reference/rest/v3/liveChatMessages/list) · [Provider schema](https://www.googleapis.com/discovery/v1/apis/youtube/v3/rest) · [Video lookup](https://developers.google.com/youtube/v3/docs/videos/list)

Map text messages and removal events, including deletions, retractions, tombstones and author bans. Ignore other event types. Use a fixed provider origin, no image fetches and no user-supplied endpoints. Verify attribution, data access and removal policies before enabling public distribution. Keep queue content session-only and provide a clear-local-data action. [Message resource](https://developers.google.com/youtube/data/live/reference/rest/v3/liveChatMessages) · [Developer policies](https://developers.google.com/youtube/terms/developer-policies) · [Branding](https://developers.google.com/youtube/terms/branding-guidelines)

## Acceptance

In an isolated show, deliver two synthetic messages. Approve one and verify Program stays unchanged. Show the approved message and verify its actual Program pixels contain that author, text and attribution. Prove the other item cannot air through the UI, Take, a Shot Layout, a hotkey or a control action. While a Show is preparing, replace or delete its approved item, then release native readiness and verify no Program promotion. Remove an item already on air and verify actual disappearance. Repeat through cancellation, reconnect, auth failure and source replacement. Inspect the review panel at 1360×768 and 1600×900 and check that long text is readable before approval. Separately exercise one controlled public test livestream with consent and record provider qualification.
